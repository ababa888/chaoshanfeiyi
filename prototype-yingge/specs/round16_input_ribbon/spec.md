# 第 16 轮规格：输入到画面连贯性 + 鼓点表示重做

范围：只改 `prototype-yingge/`。不改判定数学（判定窗口、Perfect/Good/Miss 阈值与吸附规则保持原样）。

## 1. 实测链路（已跑 `tools/input_latency.py`，24 次合成按键）

| 分段 | min | med | max |
|---|---|---|---|
| post→get | 0.02 | 0.04 | 0.05 ms |
| get→judge | 0.01 | 0.02 | 0.03 ms |
| judge→draw | 9.02 | 10.42 | 15.45 ms |
| **post→draw** | **9.06** | **10.46** | **15.51 ms** |

结论：游戏侧按键到首帧像素 = 1 帧（≤16.7ms）。系统键盘延迟（USB 扫描 + 驱动 + SDL）不计入此口径。

## 2. 定位到的两个真实原因

1. **不是 `pygame.event.get()` 造成 1–2 帧积压**：post→get 最大 0.05ms，事件在投递后的同一帧即被取出。
2. **是表现层缺少“按下去就响”的反馈**：
   - 乐器按下动画从 0px 缓入到 2px（70ms=4 帧），按下当帧位移为 0；且用的是暗一阶图（与“变亮”相反）。
   - 槽位只在判定/落定后点亮，早按（尚未到拍点）期间无中间态。
   - 行动拍/被拒按键没有任何槽位反馈。

## 3. 改动（两个点）

### 3.1 输入管线（已完成）
- `core.py`：`input_queue` + `push_input(key, t_event)` + `_drain_input()`；`update()` 首行按时间戳排序消费（稳定排序保证同时间戳按到达顺序）；判定用事件时间戳 `beat_at(t_event)`，不用帧时间；`min(t, now)` 防未来时间。
- `main.py`：键盘、手柄按钮、手柄轴、DemoDriver 四条路径统一 `game.push_input(key, now)`；`audio.key(key)` 对每次 J/K/L 下落播触键干声（独立通道，不占正式鼓点 `dong/cai`）。
- 判定数学不变：`press()` 仍 `beat_press(key, now, 0.0)`（吸附最近整拍，偏差落 Perfect）。

### 3.2 两段式反馈（待收尾）
- **本地即时（输入当帧）**：
  - `render.instrument_pose()` 改为：`age_ms==0` 当帧即 `dy=1`，`press_ms/2` 后 `dy=2`；第二返回值语义由“暗一阶”改为“高亮”。
  - `AssetBank` 新增 `instrument_lit`（`BLEND_RGB_ADD` 均匀提亮，alpha 不变，无半透明）。
  - `_draw_beat_ui` 按压时用 `instrument_lit`，保持整数像素位移与整档颜色。
  - 槽位 `_draw_ribbon_slot`：`now < clock.beat_time(beat)` → 左半格填充 `(168,126,62)` + 1px 描边脉冲（`(255,212,120)`/`(132,100,56)`，半周期 220ms）+ 键位符号。
- **拍点确认（判定后）**：`now ≥ beat_time(beat)` → 按 grade 落定：Perfect `(255,214,120)` 框 + `(52,42,18)` 底 + 120ms inflate(4,4) 金框；Good `(140,220,170)`；Miss `(226,70,62)` + 420ms 双红斜杠；其余 `(205,172,120)`。

### 3.3 谱面带（方案 A，已实现）
- 外框 `HUD_RIBBON=(272,408,660,84)`；判定线 `x=437`（左 1/4，4px 金线 + 顶部倒三角）；基线 `y=486`；格距 `66`；格宽 `54`；可见 `8` 拍（本组 4 + 下组 4）。
- 节拍：132BPM → 每拍 `0.4545s` 前进 1 格；位移 `int(round((b-beat_pos)*66))`，严格整数像素。
- 强弱：偶数拍（组内第 1/3 拍）高 `48`、奇数拍高 `34`（高度差 14px）；强拍 2px 边；当前组边框 `(110,84,64)`，下一组弱化 `(64,52,44)`。
- 乐器符号：鼓=实心圆 r9、锣=18×18 方框（实心 3px / 空心 2px）、镲=3px 斜杠。
- Perfect 金框停留 `120ms`；Miss 红斜杠停留 `420ms`。
- Boss 公示：高亮段 `2px (126,92,62)` 覆盖本循环行动拍（第 5–8 拍，对应 6 拍预警的首段）；招式名与化解键位文字移到带内顶部（`y=ry+6`，避免与一次性教学条 `(350,392,260,34)` 相撞）。
- 读招面板从 `_build_hud` 移除，不新开第三块 UI。

### 3.4 选型取舍
| 候选 | 优点 | 缺点 |
|---|---|---|
| **A 横向滚动谱面带（采用）** | 可读性最好；“还有几拍到判定线”一眼可量；与谱面/教学同一套横轴时间语言；加 Boss 6 拍只需叠高亮段；整数像素滚动成本低 | 占横向空间 660px |
| B 环形四面鼓 | 与斜俯视鼓面构图协调 | 环上“剩余时间”非线性的，预判差；Boss 多拍叠加相互遮挡；文字沿环排布易出半像素 |
| C 鼓面涟漪 | 气氛强、贴合主题 | 只能看“刚过”，看不出“还有多久”；输入状态难以表达；遮挡谱面细节 |

## 4. 验收
- `SELFTEST: PASS` + `SMOKE: PASS`。
- 新增断言：
  1. 按键到像素 ≤1 帧（合成事件当帧消费 + 同帧 HUD 乐器区像素变化；`instrument_pose(0)` 位移 ≥1）。
  2. 同帧多键按事件时间戳顺序入队（monkeypatch `press` 记录顺序）。
  3. 槽位状态机：`pending → perfect/good/miss`，且过了 `beat_time` 不再回 pending。
  4. 谱面带滚动 x 为整数；相邻拍差恰为一格 `66`。
  5. 强/弱拍高度差 > 0 且常量为整数。
  6. Boss 公示高亮段出现在 `HUD_RIBBON` 内（颜色 `(126,92,62)`）。
  7. 无第三块 UI：`HUD_READ_PANEL` 区域 alpha 全 0，且 ribbon 有内容。
- 性能：`tools/longrun_bench.py --1080`，对比上轮 avg 11.51 / p95 15.44 / peak 28.40。
- 出图 6 张：按下三帧序列 / 谱面带常态 / Perfect / Miss / Boss 预警 / 新旧同区域对比。

## 5. 已知边界
- 系统键盘延迟不计入游戏侧；工具只测 pygame 队列 → 判定 → 绘制。
- `dt_ms` 仍恒为 0：吸附最近整拍后必为 Perfect，属既有判定设计，本轮未改。
- `beat_time()` 用当前 BPM 近似反解，Fever 变速瞬间待确认态边界误差 ≤1 帧。
- `_draw_read_panel`、`_draw_slot_icon` 暂留为未调用死代码（不在本轮清理范围）。
