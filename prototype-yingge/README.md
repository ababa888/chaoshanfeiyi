# 踏鼓 · 英歌八拍原型（prototype-yingge）

独立于 `drumbeat-m0/` 的可运行小原型：潮汕英歌 × Patapon 的「八拍一循环」节奏战斗。
逻辑核心不依赖 pygame，渲染与输入各自独立；素材全部由程序化脚本生成。

## 运行

```powershell
py -3 prototype-yingge/main.py           # 正常窗口，自动演示，按 J/K/L 接管
py -3 prototype-yingge/main.py --difficulty drill
py -3 prototype-yingge/main.py --headless --auto-exit 70   # 无头实跑并批量出截图 + 遥测
py -3 prototype-yingge/tools/playtest_sim.py               # 四档模拟手难度曲线（含改前/改后）
py -3 prototype-yingge/selftest.py       # 期望 SELFTEST: PASS
py -3 prototype-yingge/tools/hud_shots.py           # 第十五轮 5 张字体验收图
py -3 prototype-yingge/tools/beat_ribbon_shots.py   # 第十六轮 6 张输入/谱面带验收图
py -3 prototype-yingge/tools/input_latency.py       # 按键→像素链路实测（合成事件）
py -3 prototype-yingge/tools/longrun_bench.py --1080  # 1920×1080 原生 HUD 帧时间
py -3 drumbeat-m0/tools/smoke_test.py    # 回归，期望 SMOKE: PASS
```

（若本机 `python` 已在 PATH，直接替换为 `python` 即可。）

依赖只有 pygame；素材由 `tools/gen_assets.py` 生成，重跑即可复现：

```powershell
py -3 prototype-yingge/tools/gen_assets.py   # 输出 assets_gen/ + manifest.json
```

## 第十六轮改动总览（输入两段式反馈 + 横向滚动谱面带）

- **链路实测**（`tools/input_latency.py`，24 次合成按键，无头）：

  | 分段 | min | med | max |
  |---|---|---|---|
  | post→get | 0.02 | 0.03 | 0.14 ms |
  | get→judge | 0.01 | 0.02 | 0.03 ms |
  | judge→draw | 10.40 | 11.12 | 14.96 ms |
  | **post→draw** | **10.45** | **11.17** | **15.04 ms** |

  游戏侧 = 1 帧（≤16.7ms）。系统键盘（USB 扫描/驱动/SDL）延迟不计入此口径。
  原 1–2 帧延迟**不是** `pygame.event.get()` 积压（post→get 最大 0.14ms），而是表现层缺反馈。
- **输入管线**：`core.Game.push_input(key, t_event)` 带时间戳入队，`update()` 首行
  `_drain_input()` 按时间戳稳定排序消费（同帧多键按到达顺序），判定用事件时间戳而非帧时间；
  键盘/手柄按钮/手柄轴/自动演示四条路径统一走这条通道。
- **两段式反馈**：
  1. 输入当帧：乐器图标**立即下沉 1px + 提亮一档**（`instrument_lit`，`BLEND_RGB_ADD`，alpha 不变），
     并播一次触键干声；槽位显示「已按键 · 待确认」半格 + 1px 描边脉冲（半周期 220ms）。
  2. 拍点确认：Perfect 金框 + 120ms inflate 外框；Good 绿框；Miss 红框 + 420ms 双红斜杠。
- **谱面带（方案 A）**：外框 `(272,408,660,84)`，判定线 `x=437`（左 1/4），基线 `y=486`，
  格距 `66`、格宽 `54`、可见 8 拍；132BPM 下每拍 `0.4545s` 前进一格，位移一律
  `int(round((beat - beat_pos) * 66))`。强拍高 `48`、弱拍高 `34`，当前组边框亮、下一组弱化。
  格内符号：鼓=实心圆、锣=方框、镲=斜杠。Boss 公示改为谱面带上的 2px 高亮段 + 带内文字，
  不再单独开读招面板；一次性教学条上移到 `y=356` 避免遮挡。
- **选型理由**：横向时间轴可读性最好、能直接量“还有几拍到判定线”、与谱面/教学共用语言、
  Boss 多拍预警只需叠段；B 环形的时间非线性、C 涟漪看不出剩余时间，均放弃。
- **性能**（`tools/longrun_bench.py --1080`，10969 帧，标准难度完美手）：
  avg **10.89ms** / med 10.02 / p95 **14.81** / peak **23.52**（上轮 11.51 / 15.44 / 28.40）。
  谱面带增量被左栏缓存与 HUD arena 复用抵消，整帧反而略降。
- **截图**：`52_input_press_3frames.png`（同一按键三帧：空 → 待确认 → 锁定）、
  `53_ribbon_normal_1080p.png`、`54_ribbon_perfect.png`、`55_ribbon_miss.png`、
  `56_boss_ribbon_warning.png`、`57_ribbon_before_after.png`（旧四拍条 / 新谱面带同区域）。
- **自测新增**：按键到像素 ≤1 帧、同帧多键按时间戳有序入队、待确认→锁定状态机、
  谱面带整数滚动与每拍一格、强弱拍高度差 14px、Boss 预警落在谱面带、无第三块 UI 面板；
  `SELFTEST: PASS` + `SMOKE: PASS`。

## 第十三轮改动总览（单点透视收敛 + 148 单位长图）

### 透视模型（针孔/单点，`pseudo3d.py`）
- `scale(v) = (FOCAL + DEPTH0) / (FOCAL + depth(v))`，`depth(v) = DEPTH0 + (v - V_NEAR) * DEPTH_GAIN`；
  `sx = VPX + (u - cam) * KX * scale(v)`，
  `sy = VPY + Y_SPAN * scale(v) + (u - cam) * tilt_px() * scale(v)`。
- 常量：`VPX,VPY=360,120`、`KX=46`、`Y_SPAN=190`、`FOCAL=4`、`DEPTH0=6`、`DEPTH_GAIN=1.35`、
  `V_NEAR,V_FAR=-6,6`。`tilt_px() = tan(slope_deg) * KX`，坡度按段落 8°/10°/12° 切换。
- 反算闭式：`s=(dy-dx*tilt/KX)/Y_SPAN` → `depth` → `v` → `u`，往返误差 0 像素；
  不做二分搜索。
- 常数 u 的两条边线严格交于消失点 `(VPX, VPY)`；地面矩形格因此收敛为梯形。

## 第十二轮改动总览（斜俯视伪 3D 斜面）

### 投影模型（`pseudo3d.py`，全部收口在这里）
- 世界平面 `(u,v)`：`u` 沿下坡方向（屏幕右下），`v` 横跨坡宽（屏幕右上偏内）。
- 映射：`sx = ox + u·Ux + v·Vx`，`sy = oy + u·Uy + v·Vy`
  （`Vy<0` 表示 v 正方向在屏幕上移，等价于 `oy + u·Uy − v·|Vy|`）。
  最终系数 `U=(0.94,0.34)`、`V=(0.55,-0.30)`，`PX_PER_UNIT=48`，`ORIGIN=(370,268)`。
- `V` 的 x 分量由参考 `-0.55` 改为 `+0.55`：原值在 960×540 下与 U 轴近似共线，坡面会压成一条细带；
  改后两轴张开成可读等距斜面（唯一偏离参考值的系数）。
- 所有落点 `round` 到整数像素；`roundtrip_px()` 保证 `(u,v)→屏幕→(u,v)→屏幕` 误差 0。
- 深度分档选**恒定 1×、不做连续缩放**：像素贴图非整数倍缩放会产生灰边/抖动；
  纵深改用 v 排序、真实遮挡、脚底 y 与固定阴影表达。阴影统一 `dx=-20, dy=13`（太阳右上）。

### 二/三阶段补打

| 规则 | 值 |
| --- | --- |
| 开放阶段 | 仅二阶段（65–33%）与三阶段（32–0%）；一阶段不开放 |
| 触发 | 错令或窗口内漏拍，伤害**暂不结算** |
| 窗口 | 失败后 **1 拍**（132 BPM 约 0.45s），倒计时环耗尽即失败 |
| 输入 | 1 拍内任意时刻（可快速连按）重新收齐正确四拍；不占下一组指令槽 |
| 成功 | 伤害 **×0.5**、连击与鼓劲槽保留、按 **Good 计**（不算 Perfect）、**不累积 Fever** |
| 失败/超时/序列错 | 恢复原规则：全额伤害、连击与鼓劲槽清零、Fever 结束 |
| 次数 | **每招一次**（`BossAttempt.makeup_used`），补打失败后同一招不再给第二次 |
| 新手保护 | 前 3 招免罚优先，不与补打叠加 |

可感知的确定结果，而不是先吃全额再退款。

## 操作方案

**三键四拍成令：J = 鼓、K = 锣、L = 镲。** 不采用「四个方向键对应四拍」或「一排四个鼓键」。
理由：

1. 四拍命令需要三个音节的重复与交错（JJJJ / KKKK / LLLL / JKJK / LKLK / JJKK / KLKL），
   三键就能表达全部指令，与 Patapon 的 PATA / PON / CHAKA 三音节结构同构；
2. 三键全部落在左手主键区，单手可盲打，不会像方向键那样与移动/菜单冲突；
3. 高级阵法用交错序列区分，不再额外占键；
4. 键位写在 `config/controls.json`，可改成 Z/X/C 或任意字母；
5. 手柄按钮 0/1/2 映射同一套三令，扳机/摇杆轴接口已在 `input_map.py` 预留；
6. 输入缓冲 = 按键吸附最近整拍（±160ms），早按/晚按都落在同一拍槽位，超窗才判 Miss。

| 命令 | 四拍 | 效果 |
| --- | --- | --- |
| 猛虎下山（攻） | J J J J | 三兵种齐击，Perfect 增伤 25% |
| 长蛇突进（行） | K K K K | 全队推进，Perfect 额外前移 |
| 铁壁守阵（守） | L L L L | 4 拍内承伤 ×0.4 |
| 锋矢阵 | J K J K | 攻 ×1.30、减伤 -10%、行军 ×1.15 |
| 龟甲阵 | L K L K | 攻 ×0.80、减伤 +40%、行军 ×0.75 |
| 双龙出海 | J J K K | 攻 ×1.10、减伤 +5%、行军 ×1.45 |
| 猛虎下山阵 | K L K L | 攻 ×1.75、减伤 -30%、行军 ×0.60、攻击后硬直 2s |

`P` 键打开三好汉定妆照 lineup，`M` 键打开 5×5 克制矩阵速查。
`Z` 切换 zoom 两档（1.0× / 0.75×，可视 20.0 / 26.7 世界单位）；`V` 循环景深调试（关远景 / 关中景 / 关近景）。

## 循环与规则

- **8 拍一循环**：前 4 拍收令，第 5 拍（行动重拍）统一起手结算，后 4 拍行动；
  动作相位与全局节拍对齐，同拍起步。
- **自动行军**：每拍基础前压 0.52 世界单位，连续合拍最多 0.92；
  再乘阵法 `march` 倍率。强拍抬脚、弱拍落步，停步时扬尘。
- **三兵种**：盾兵（46 HP / 35% 护甲）、鼓手（34 HP / 18 攻 / Fever 双击 1.35×）、
  矛兵（30 HP / 14 攻 / 长杆 / Fever 穿甲）。前排倒下后由下一位承伤。
- **Boss 破阵**：抬手在重拍前 0.08 拍（≈36ms）公示，图标 + 名称 + 落点 + 阵地高亮脉冲；
  接下来 4 拍必须输入匹配指令：
  - AOE（横扫 / 鼓吼）→ `L L L L` 架挡；
  - 单体重击（重砸 / 冲锋）→ `K K K K` 后撤/侧闪；
  - 抓取（鼓爪）→ `J J J J` 突击。
  错令或超时吃全额伤害（半血后 ×1.25）；4 拍全 Perfect 且命令匹配 → 极限破阵。
  **意图谱**：三阶段加权（起势/翻江/绝命），开战 2 拍缓冲、同招不三连、AOE 间隔 ≥6 拍；
  进入新阶段首招长公示 4 拍；连续同类型第二招带「长蓄」金圈与低沉锣声（不同音色）。
  谱面可调 `config/boss_score.json`，同 seed 完全复现。
- **极限破阵**：Boss 硬直 1.9s，无伤，队伍直接进入 Fever；
  硬直期每个行动拍自动追打 `Σatk × 0.55`（Fever 时 ×2）。
- **Fever 满堂彩**：Perfect +2、Good +1，标准档 14 点满槽（=7 连 Perfect）；操练档 10 点。
  Fever 持续 10s（操练 12s），伤害 ×2，Perfect 窗口 +20ms（45→65）、Good +30ms（100→130）；
  极板目标 BPM 148（上限 150）。断档或超时退出，槽清零并冷却 4s（操练 3s）。
  Fever 中再打出极限破阵 → 时长叠加 0.8 倍（最多 3 倍总时长）并补满槽。
- **难度**：`1` = 操练（窗口 ×1.35、敌伤 ×0.7、Boss 420 HP、Fever 10 点/12s/冷却 3s），
  `2` = 标准（±45/±100/±160ms、Boss 600 HP、Fever 14 点/10s/冷却 4s）。
- **死亡与重开**：三兵全倒 → 全军覆灭；Boss 倒下 → 鼓王伏诛；`R` 重开。

## 关键数值与理由

| 数值 | 取值 | 理由 |
| --- | --- | --- |
| 默认 BPM | 132 | 英歌快板常见区间 130–140，132 的拍距 ≈454.5ms，四拍窗口 1.82s，适合“听两拍再反应” |
| 判定窗口 | ±45 / ±100 / ±160ms | Perfect 45ms 要求真合拍；Good 100ms 容纳卡顿；160ms 之外判 Miss |
| Fever 放宽 | Perfect +20 / Good +30ms | 放宽约 44% / 30%，奖励期更敢打，但仍需在拍上 |
| 极板上限 | 150 BPM | 拍距 400ms，8 拍循环 3.2s；再快则 4 拍输入窗口 <1.6s，且与 `drumbeat-m0` ADR-001 的 150 BPM 上限一致 |
| Fever 目标 | 148 BPM（132×1.12） | 明显“提速”但留 2 BPM 余量，避免卡在硬上限抖动 |
| 硬直时长 | 1.9s | ≈4.2 拍（标准档），足够打 4 次踏点追击，又不会让 Boss 长期站桩 |
| Fever 时长 | 10s / 冷却 4s | 约 2.6 个循环，能覆盖一次变阵+一次破阵；冷却防止无限叠 |
| 鼓劲槽 | 14 点（7 连 Perfect） | 约 1.8 个循环可攒满，节奏上“两轮一高潮” |
| 自动行军 | 0.52 → 0.92 / 拍 | 8 拍可推进约 3.6–7.4 单位；双龙 ×1.45 约 5.2–10.7，避免瞬间贴脸 |
| 坡度 | 10°（tan=0.176） | 8° 不够“俯冲”，12° 会让坡面在 720p 内压到 HUD；10° 兼顾压迫感与可读性 |
| 下坡速度 | +11%（起步）→ +27%（连拍拉满） | 加速度 0.40→1.0 用 5 拍爬满；奖励冲锋但保留站位判断 |
| 上坡代价 | ×1.35（速度 0.74×） | 只作用于破阵失败回撤，不做惩罚性爬坡；1.0–1.5 区间取偏中值 |
| 击退 | 下坡 ×1.45 / 上坡 ×0.67 | 下坡更远、上坡更短；破阵 0.9→1.31，回撤 0.55→0.37（世界单位） |
| Boss 阶段 | 100–66 / 65–33 / 32–0% | 三阶段招式池递进；开战 2 拍缓冲，阶段切换首招必为 4 拍公示 |
| AOE 间隔 | ≥6 拍 | 8 拍一循环的公示天然间隔 8 拍；规则写进谱面，防止未来加“短期公示”时连喷 |
| 破绽增益 | 伤害 ×1.10–1.35 | 矩阵数值；克制反馈即时可见，避免充能/缩短公示的副作用 |
| 视觉倾斜 | 10°（8–12° 可调） | 与坡角一致，整体压坡但不至于像滑倒；`visual_tilt` 可一键关闭 |
| 冲锋前倾 | 0–6°（5 拍爬满） | 只叠在行军加速度上；急停归零，读得出“冲”与“走” |
| 受击后仰 | -6°（短暂） | 从坡面倾斜里减，够可读又不破坏贴坡 |
| 倒地滚动 | 30px / 0.55s | 缓出三次方，顺坡滚一小段就停，避免无限滑 |
| Boss 台高优势 | 近战 ×1.35 / 仰攻 ×0.85 | 上下差约 1.59 倍；破阵落台立即归 1，地形关系直接改变 |
| 落台硬直 | 3.4s（普通 1.9s） | 破阵奖励窗口约 7.5 拍，够换阵+追击，但不至于白打 |
| 一阶段公示 | 6 拍（二/三阶段 4 拍） | 给新手多 2 拍读招；输入窗口仍 4 拍，熟练档不变 |
| 新手免罚 | 前 3 招、伤害 ×0 | 与“只公示不惩罚”同义；不清连击/Fever，避免负反馈 |

## 与旧设计的差异说明（第三轮以新需求为准）

- 旧版 Boss 是“每循环公示一次、用一条指令化解”；本轮改为**抬手即公示 + 4 拍序列化解 + 全 Perfect 极限破阵**。
- 旧版 Fever 是攻击 ×1.5、8 点触发、只增伤；本轮改为**×2、14 点（操练 10）、有持续时间/冷却/窗口放宽/叠加**。
- 旧版“按指令才动”；本轮改为**自动行军**，不打指令也保持队列前压，脱拍才停步。
- 旧版 2 阵（锋矢/龟甲）；本轮新增**双龙出海、猛虎下山**，共 4 阵并给出克制关系。
- 旧版音效与动画各自计时；本轮统一到 `beat_pos` 拍位数据，音画同源。

## 已知边界

- **8px 中文的笔画密度**：HUD 已改成 960×540 原生排版，文字与边框不再经历重采样（截图 19/20 可验）；
  但 8px 逻辑字号的中文只有约 8×8 点阵，“围 / 阵 / 减 / 衰”这类多笔画字在 3× 放大下能看出笔画粘连，
  呈现尺寸只有 16px。已通过合并标签（见“HUD 原生排版”）把最密的小字删到 4–6 字；再小就只能改 10px 并加宽面板。
- **ASCII 只有大写**：5×7 点阵按 `upper()` 映射，小写字母显示为大写；当前 HUD 只用大写键位与数字，
  没有小写文案需求。
- **缓存上限**：文字缓存 800 条，动态数值（HP、连击、计时）每出现一个新值就新增一条；
  极长局（数十分钟）会触发最早条目淘汰并重新栅格化，单帧额外开销可忽略，但不是零。
- **变体的可见边界**：为保证换图不跳变，两套远景的左右边列刻意完全一致（海平线/雾带/透明屋檐），
  因此变化集中在画面中段的峰位与云带；远景观感仍以 960px 为周期，极端长距离推进时
  峰型会再次循环（只是相邻周期不再是同一张图）。
- **补打窗口与下一组输入重叠**：1 拍窗口偶尔会盖住下一循环第 0 拍，期间的按键优先计入补打缓冲，
  相当于用一拍指令空间换补救机会；这是有意保留的代价，模拟手里也按此规则执行。
- **补打只作用于 Boss 化解**：普通杂兵的脱拍/漏拍不走补打，仍按原连击规则处理。
- **0.75× 档是非整数精灵缩放**：贴图按 `0.75×0.75=0.5625` 做 nearest 缩放，个别 1px 描边在镜头平移时
  会有轻微“跳动/闪烁”；1.0× 档不受影响。HUD 坐标两档一致，但世界层信息量更大、角色更小。
- **三层平铺的重复感**：远景 2 套 / 中景 3 套变体已按世界平铺序号交替，相邻周期不再是同一张图；
  但每套自身仍是 960px 周期，极长推进后仍能认出同一套变体。近景剪影仍只有两种姿态、单套平铺。
- **视差是条带近似**：每 48px 一条带按坡度做纵向偏移，坡面很陡时（>12°）条带边缘可能出现 1px 台阶；
  当前 10° 下不可见。
- 占位级程序化美术；好汉为 48×64 基础像素的 chibi 比例（3× → 144×192），22 帧是姿态差分而非手绘逐帧，
  没有 IK/骨骼，武器弧线只在峰值帧用姿态与特效表达。
- 坡面已改为 `(u,v)` 斜俯视平面 + 三棱柱侧面，但仍是**正交/斜二测投影，没有透视收敛**：
  同等大小的角色在远处不会缩小，纵深只靠 v 排序、真实遮挡、落点 y 与固定阴影表达；
  大幅 v 跨度或角色贴得极近时，遮挡边缘仍可能出现“谁压谁”的硬切换。
- 倾斜是**整张贴图绕底边中点刚体旋转**（不是骨骼/IK），因此只有整体前倾，没有脊柱弯折、膝踝配合；
  上坡只发生在破阵失败回撤，没有手动爬坡段。
- Boss 石台的高度优势只作用于**近战伤害**（×1.35 / 仰攻 ×0.85），不做真实碰撞/落脚高度判定；
  破阵落台后优势消失并给 3.4s 长硬直，但 Boss 仍按同一套 8 拍谱面出招，没有“台下专属招式”。
- 新手免罚（前 3 招 ×0）与一次性教程只在 Boss 战生效；垃圾兵阶段没有引导，
  教程提示是固定文案，不根据玩家实际错误动态改写。
- 敌人 AI 只有「逼近 + 按拍攻击」，不会绕后或打断；Boss 已改为可 seed 三阶段权重谱，
  但仍是“单 Boss + 固定 8 拍循环”，没有多 Boss 切换或跨阶段连招打断。
- 克制矩阵已接入命中结算；但 AI 对手不会主动利用矩阵反制，模拟手也固定阵型，
  真人换阵的决策负担尚未验证。
- **HUD 动效是纯表现**：乐器按压、四拍槽落位、预测图标、破阵印章、结算面板都不参与判定；
  `beat_press` 的窗口/数学一行未改，动效只读 `game.press_times / press_grades / beat_pos`。
- **涨破与 Fever 不等逻辑**：核心在鼓劲槽满的同一帧就进入 Fever；`gauge_burst_ms` 只是
  HUD 在 Fever 已生效后补播的 220ms 视觉涨破，没有把 Fever 生效延后。
- **白闪按帧数计时**：`break_flash_frames=3` 固定 3 个 draw 帧；若帧率很低，墙钟时长会超过 3/60s。
- **结算淡入是 4 档固定 alpha**（0/85/170/255），不是线性渐变；这是为了守住“不做逐帧插值 alpha”
  的动效纪律，观感上是分档淡入。
- **预览 GIF 有调色板损失**：480×270、6×6×6 调色板近似，只用于看动效节奏；锐度以
  1920×1080 的 PNG 与 `selftest` 断言为准。
- **锣的贴图是代码现画**：素材库没有独立锣图，`_make_gong()` 用无抗锯齿同心圆绘制；
  与既有 96×96 素材风格一致，但不是 `gen_assets.py` 产物（换素材需同步改这里）。
- 模拟手数据（本轮后）：完美 100% / 7.8s，熟练 100% / 9.1s，
  新手改后 20% / 41.2s、第一阶段存活 100%（改前 0% / 0%）。
  新手胜率仍偏低，主要败在二三阶段 4 拍公示；**判定窗口未改**，避免损伤熟练玩家收益。
- 判定仍是最简三档窗口，未接入 `drumbeat-m0` 的 `judgement.py` 数学（按要求不碰）。
- **第十六轮的系统键盘延迟**：`input_latency.py` 只测 pygame 队列 → 判定 → 绘制；
  USB 扫描周期、OS 驱动、SDL 事件泵的延迟在游戏外，未计入 10.46ms。
- **`dt_ms` 仍恒为 0**：按键吸附到最近整拍后必定 Perfect，这是既有判定设计，本轮只改输入通道与表现。
- **`beat_time()` 是等速近似**：Fever 变速或分段 BPM 切换瞬间，待确认态边界可能有 ≤1 帧误差。
- **未调用死代码**：`_draw_read_panel` 与旧 `_draw_slot_icon` 已不在 `_build_hud` 路径中，暂留未删。
- 手柄仅在 Windows 默认 pygame 驱动下验证接口存在，未实机校准。
- 无头实跑 70s 的机器人是“完美演奏”脚本，Boss 血量与破阵次数来自该脚本，不代表人类难度。

## 第十八轮：战前场景（选将 + 新手指南）

- **流程**：`Title → Roster → Guide → Battle`；暂停菜单可重进一次指南（第二项用过即禁用），
  `ESC` 逐级返回，`G` 在指南内跳过整段。键盘可完成全流程，鼠标只做可选补充。
- **选将**：3×3 九宫格（84px 格 / 96px 间距），武松/林冲/李逵可选，另 6 格为锁定态
  （`?` + 两行解锁条件）；锁定格 `ENTER` 不生效、只弹提示，悬停可看条件。
  选中格 4px 金框（逻辑 4px = 输出 8px），右侧 128px 定妆照 + 脸谱/兵种/技能/效果/推荐阵法/站位/开场词。
  预览切换是 ±6px、每帧 2px 的整数像素滑入（≈50ms），无淡入淡出。
- **领队**：选 1 名领队写 `config/settings.json` 的 `leader`，决定开场阵型、推荐阵法与顶部台词；
  另外两人仍随队上场。三位都已实跑开局（`selftest` 覆盖）。
- **指南 6 步**：这是鼓 / 四拍成令 / 三种乐器 / 阵法 / 读谱破阵 / 个人校准；
  每步有可交互目标，未完成时 `ENTER` 不前进（底栏显示门槛文案）。判定仍走
  `core.judge_press`，**窗口数值未改**；教学内 Miss 只给针对性纠正，不计连击惩罚。
- **校准**：第 6 步 8 拍自由敲，取平均偏移钳 ±120ms 写入 `input_offset_ms`；
  战斗输入时间戳按 `bn - offset/1000` 修正（钳到 `clock.start_time`），重开保留；跳过记 0。
  遥测写入 `playtest/guide.csv`（leader/skipped/steps_done/calib_ms/retries）。
- **性能（1920×1080，只计场景绘制）**：title 5.72/7.33/8.26ms、roster 6.57/8.73/10.68ms、
  guide_step2 6.22/8.01/9.81ms、guide_step5 6.31/8.02/10.60ms、guide_calib 6.24/8.04/10.82ms、
  pause 1.54/1.66/3.64ms（avg/p95/peak）。整关战斗复测 avg 11.62 / p95 15.91 / peak 30.92ms。
- **已知边界**：
  - 字库（Fusion Pixel）在 10px 网格缺 `镲`、全网格缺 `✓`/`≤`：UI 里完成标记改用「过」，
    三乐器说明行降到 8px 网格，避免出现实心方块。
  - 锁定格的解锁条件目前是**纯展示文案**，未接关卡进度/成就系统；6 格全部不可解锁。
  - 指南重进只有一次（`replay_used` 每局重置），不是无限入口。
  - 校准只算平均偏移，不区分早/晚抖动，也不修正标准差；极端连打会被均值稀释。

## 第十九轮：鼠标全流程可玩 + 渲染缺陷修复 + 指南重绘

### 闪退根因（P0）

无头复现脚本 `tools/mouse_fuzz.py --repro` 在 Title 第一击即复现：

```
File "prototype-yingge/main.py", line 530, in <module>
    token = flow.click(lx, ly, now)
TypeError: Flow.click() takes 3 positional arguments but 4 were given
```

`main.py` 早先按「场景点击需要当前时间」传了 3 个实参，而 `scenes.Flow.click` 仍是旧签名
`click(self, x, y)`，事件循环第一帧鼠标按下就抛异常。Title / Roster / Guide / Pause
四个场景此前也没有任何鼠标分支，所以修签名只是第一步。

**修法**：`Flow.click(x, y, now=0.0)` 按场景分派（`_guide_click` / `_pause_click`），
`Flow.hover` + `Flow.hotzones` 与渲染共用 `scenes.py` 的同一份矩形常量；Roster 点击走
`roster_cell_at` 的索引范围校验，锁定格在 `confirm()` 内早退，窗口坐标经
`SceneUI.logical_pos` 归一化并夹到 0..959/0..539。没有整体 `try/except`。

### 坐标映射

`logical_pos` 用整数映射 `(pos - 呈现偏移) * VIEW_W // 呈现宽`，1× / 1.5× / 2×
以及非 16:9 黑边窗口都反算回 960×540 逻辑坐标；自测断言覆盖四种窗口。

### 鼠标路径（键盘全部保留）

- Title：点「ENTER 点将开始」整条 → Roster。
- Roster：悬停看详情、点可选格即确认领队并进 Guide；点锁定格只弹条件提示。
- Guide：悬停步骤列表高亮，点击已完成步骤可回跳；大鼓/锣/镲三块乐器就是 J/K/L 键位牌，
  点鼓面等价按 J；「下一步」未达条件为禁用态（暗底灰边灰字，点了无效），
  「开始校准 / 完成校准」「跳过本步」「跳过指南」均可点；每步完成即打勾并推进进度。
- Battle 暂停：三项菜单全部可点。`F2` 切换 1px 热区覆盖，`F3` 切换调试层（默认关）。

### 渲染缺陷

- **文字叠印**：格子头像 PNG 底部烘焙了一行字幕，渲染又在同一格画「武松 / 领队」标签，
  两层字压在一起；同时 8px 网格 + 2px 硬投影让小字笔画并线。修法是裁掉头像字幕区
  （`_face_at` 取 `(64,24,128,128)`）、场景文字默认不画投影、最小字号回到 10px 网格
  （输出 20px）。像素探针断言：文字区域投影像素 `shadow_px=0`，同帧同内容文本无重复调用。
- **调试浮层**：截图右上「N 个任务运行中」与右下角方块来自 IDE，不在游戏绘制内；
  游戏自身调试层改为 `SceneUI.debug_overlay`，默认 False，`F3` 显式开启。
- 字库 grid10 缺「镲」，三乐器说明与键位牌统一写作「钹」，不再降字号。
